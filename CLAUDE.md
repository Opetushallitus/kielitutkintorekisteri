# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kielitutkintorekisteri (kitu) — OPH's register for language-exam data. Virkailija-facing Spring Boot app that also forwards records to the KOSKI service so they can be shown to citizens in Oma Opintopolku. Primary documentation and external API descriptions are linked from `README.md`.

## Toolchain

All language/tool versions live in `.mise.toml` and are installed automatically by `scripts/start_local_env.sh`. Java 25 + Kotlin 2.4.10, Node 24, Maven 3.9, ktlint, prettier, shellcheck, aws-cli, esbuild, humanlog. `AWS_PROFILE=oph-ktr-dev` and `SPRING_PROFILES_ACTIVE=local` are set by mise.

## Common commands

```shell
# One-shot dev env setup (installs mise deps, Playwright browsers, starts tmux with db+server).
# Pulls secrets from AWS Secrets Manager via the oph-ktr-dev profile.
./scripts/start_local_env.sh
./scripts/start_local_env.sh --setup-only   # skip tmux/containers

# Run the server standalone after the DB is up (wraps mvnw spring-boot:run + humanlog).
./scripts/start_local_server.sh

# Just the DB + Jaeger
docker compose up -d

# Backend build/test (in server/)
./mvnw package               # full build with tests
./mvnw test                  # tests only
./mvnw test -Dtest=OidTest   # single test class
./mvnw test -Dtest=OidTest#methodName

# Formatting (ktlint + prettier + shellcheck). CI runs the same script.
./scripts/check-formatting.sh
./scripts/format.sh          # auto-fix

# E2E Playwright (in e2e/)
npx playwright test
npx playwright test --ui
TEST_WORKERS=4 npx playwright test   # max 4

# Infra (in infra/)
npm run diff/dev
npm run deploy/dev
TAG=$(git rev-parse HEAD) npx cdk deploy 'Dev/**'
```

Backend tests spin up PostgreSQL via Testcontainers — Docker must be running. The Playwright suite expects the app's Maven build to launch it; see `e2e/README.md` for how to attach to an already-running IDEA debug session (`reuseExistingServer: true`).

**After switching branches, run `./mvnw clean` first.** Flyway reads migrations from the classpath (`target/classes/db/migration`), and neither Maven nor the Kotlin compiler deletes class/resource files whose source has disappeared — so a migration belonging to another branch keeps running against every fresh Testcontainers database. The symptom is a `column "…" does not exist` failure in tests the source tree says should pass.

## Architecture

### Layout

- `server/` — Spring Boot 4.1.1 + Kotlin backend. Source roots are `src/main/kotlin` and `src/test/kotlin` (configured in `pom.xml`, not the Maven defaults). Packages under `fi.oph.kitu/` are organized by **feature domain**, not by layer.
- `infra/` — AWS CDK (TypeScript) app. `bin/infra.ts` wires four stages: `Util` (shared ECR repo + GitHub Actions roles), then `Dev`/`Test`/`Prod`. Each env stage composes stacks (`service-stack`, `db-stack`, `network-stack`, `connections-stack`, `alarms-stack`, `log-groups-stack`, `backups-stack`, `route53-health-checks-stack`, `koski-audit-logs-integration-stack`, ...). `bastion-stack` and `ecs-rds-proxy-stack` were **removed** in `253dc088` — don't go looking for them. Deploys pick the container by `TAG` env var.
- `e2e/` — Playwright tests against a real server + Postgres.
- `scripts/` — bash helpers for local env, AWS profile/secret setup, tmux orchestration.
- `docs/` — published to GitHub Pages (DB schema diagrams via SchemaSpy, component UML per environment, db-scheduler docs).

### Feature domains (server packages)

Each domain typically contains its own `*ApiController`, `*ViewController` (server-rendered HTML via `kotlinx.html`), `*Service`, `*Repository`, entities, and `*ScheduledTasks`:

- `vkt/` — Valtionhallinnon kielitutkinnot
- `yki/` — Yleiset kielitutkinnot (suoritukset + arvioijat). Records arrive from Solki as **JSON pushes** (`POST /yki/api/suoritus`, `POST /yki/api/arvioija`). The old Solki **CSV import pipeline was removed** (commits `279bd81f`, `d160c1f1`, `ff82bc5a`) — don't go looking for a parser: `csvparsing/` is now **export-only**. **Versiointi / muuttumattoman datan tunnistus:** every push appends a row to `yki_suoritus` (`unique_suoritus` = `(solki_id, last_modified)`, and `last_modified` is `Instant.now()` at ingest, so ON CONFLICT never dedupes). The only guard is `YkiSuoritusRepository.save`, which compares the incoming entity against `findLatestBySolkiIds(...)` via `equalsIgnoringAnnotated(..., "DB")` and skips the write when they match. **Any entity field kitu writes itself — and that Solki therefore never sends — must carry `@IgnoreForEquality("DB")`**, or it diverges after the first write and every later push appends a no-change version (this was the cause of the duplicate history rows in prod: `koskiOpiskeluoikeus`, `koskiSiirtoKasitelty`, `arviointitilaLahetetty`, `arviointitilanLahetysvirhe`, `tarkistusarviointiHyvaksyttyPvm`). **The trap:** ignoring a field also makes kitu's _own_ write of that field a no-op, so such call sites must pass `forceWrite = true` — see `KoskiService`. Two further normalizations run before the comparison so that what we compare is what actually round-trips: `withTallennettavaTarkistusarviointi` (a tarkistusarviointi is reachable only through `yki_osakoe_tarkistusarviointi`, so one with no linked osakoe is unstorable and gets dropped; empty `arvosanaMuuttui` reads back as SQL NULL) and `withHyvaksyttyTarkistusarviointi` (`TARKISTUSARVIOINTI_HYVAKSYTTY` is kitu's own tila, so an incoming `TARKISTUSARVIOITU` is promoted to it before comparing — otherwise a re-push would silently revert the virkailija's hyväksyntä).
- **YKI-arvioijarekisteri — tila lasketaan, ei talleteta:** `yki_arviointioikeus.tila` on **vanhentunut** (V121: nullable, ei defaultia). Kitu kirjoittaa aina NULLin ja tila lasketaan kauden päivistä `Rekisterointitila.laske`ssa (PASSIVOITU jos päättymispäivä < tänään, TULEVAISUUDESSA jos alkupäivä > tänään, muuten AKTIIVINEN; päättymispäivä on inklusiivinen). **Vain tallennettu `PASSIVOITU` ohittaa laskennan** — tallennettu `AKTIIVINEN` sivuutetaan, koska V117 täytti sarakkeen sillä eikä se kanna tietoa. Ainoa ei-tyhjän arvon kirjoittaja on Solkin push (`Tallennuslahde.SOLKI`). Sama sääntö on kirjoitettu kahdesti — Kotliniksi ja `Rekisterointitila.SQL`:ksi listanäkymän suodatusta ja lajittelua varten — ja `YkiArvioijaTilaSqlTest` on ainoa asia joka pitää ne yhtenevinä. Listakysely **kääritään alikyselyyn** (`SELECT * FROM (...) arvioijarivi`): ilman sitä `ORDER BY tila` kaatuu (`ORDER BY "tila" is ambiguous`) ja WHERE osuisi hiljaa vanhentuneeseen sarakkeeseen, koska aliakset eivät näy WHERE-lauseessa. Päivä sidotaan parametrina (`:tanaan`) `TimeService`ltä, **ei** `CURRENT_DATE`:na — muuten kiinnitetty testikello ei ohjaa SQL:ää. Seuraukset: passivointi **päättää kauden** tähän päivään (ja vain kiristäen — muuten klikkaus pidentäisi vanhentunutta oikeutta), joten merkintä lukee "Aktiivinen" passivointipäivän loppuun; passivointinappi näkyy ehdolla `passivoitu == null`, koska säilytysajan alkuhetki on saatava asetettua myös luonnollisesti päättyneelle merkinnälle; ja `jatkorekisterointi` johdetaan (`kaudenAlkupaiva > ensimmainenRekisterointipaiva`) eikä tule enää lomakkeelta.
- **YKI-arvioijarekisteri — arviointikausi on master, `yki_arviointioikeus` projektio:** kausi on **arvioijakohtainen**, ei kielikohtainen (OPH: _"henkilöllä ei ole päällekkäisiä arviointikausia vaan kaikilla sama kausi"_), ja elää V122:n `yki_arvioija_arviointikausi` + `..._oikeus` -tauluissa, joilla on pysyvä id. Virkailija lisää, muokkaa, passivoi ja poistaa kausia tietosivulta (`/yki/arvioijat/{id}/kaudet/**`). `yki_arviointioikeus` on **johdettu**: `Kausiprojektio` valitsee projisoitavan kauden (voimassa oleva > tuleva > viimeisin päättynyt) ja `YkiArvioijaKausiRepository.paivitaProjektio` kirjoittaa sen — **vain jos jokin arvo tosiasiassa muuttui**, muutoin yöllinen ajo leimaisi koko rekisterin muokatuksi ja lähettäisi sen uudelleen Solkiin. Näin `Rekisterointitila.SQL`, listanäkymä ja Solki-lähetys jatkavat ennallaan. Kolme ansaa: (1) valinta riippuu kuluvasta päivästä, joten projektio vanhenee kun tuleva kausi alkaa — sen korjaa `kitu.yki.scheduling.paivitaArvioijaProjektiot`, joka on **kytketty `integraatioKaytossa`-lippuun** — täysi sisääntuleva push kirjoittaa projektion koskematta kausimasteriin, joten taulut ovat taatusti eri linjoilla ja koko rekisterin yliajo vanhentuneesta masterista työntäisi sen lisäksi Solki-lähetysjonoon; (2) **säilytysaika ei saa lukea pelkkää projektiota** — `Sailytysaika.ALKUHETKI_SQL` ottaa `GREATEST`in projektiosta ja masterista ja `poistaSailytysajanYlittaneet` tarkistaa erikseen, ettei masterissa ole voimassa olevaa kautta, koska muuten vanhentunut projektio poistaisi yhä voimassa olevan merkinnän; (3) **arvioijatason passivointi katkaisee kaudet ennen `tallenna`a**, koska `tallenna` synkronoi kaudet oikeuksista — väärässä järjestyksessä syntyy uniikkiehdon rikkova duplikaattikausi. **Hallintopäätöksen ASHA-numero kuuluu kaudelle**, ei arvioijalle (V124): jokainen kausi on oma hallintopäätöksensä, joten arvioijatasolla jatkokausi olisi ylikirjoittanut edellisen viitteen. Numero kulkee myös projektioon, jotta listanäkymän haku, lajittelu ja CSV jatkavat ennallaan. Vanhentuneet kielet (`SWE10`, `ENG11`, `ENG12`) **eivät kuulu kausiin** lainkaan: ne jäävät jäädytetyiksi `yki_arviointioikeus`-riveiksi ja näkyvät tietosivulla omassa vain-luku-osiossaan. `yki_arvioija_kausi` säilyttää nimensä mutta on nyt pelkkä **muutosloki** (`toimenpide`-sarake, ei uniikkiehtoa) — uudelleennimeäminen rikkoisi rinnakkain ajossa olevan vanhan sovellusversion tietosivun. §2.4:n "kaikilla kielillä sama kausi" ja "uusi kieli perii voimassa olevan kauden" eivät ole validointisääntöjä vaan **rakenteellisia**: kaudella on yksi päiväpari ja N kielriviä.
- **YKI-arvioijarekisteri — integraatiokytkin ei koske käsin lähetystä:** `kitu.yki.arvioijarekisteri.integraatio.enabled` estää **automaattisen** lähetyksen Solkiin (tallennuksen jälkeinen synkroninen yritys, `lahetaLahettamattomat`, `SolkiArvioijaScheduledTasks` ja `paivitaArvioijaProjektiot`), mutta **ei** virkailijan tietosivulta painamaa "Lähetä uudelleen Solkiin" -painiketta: se kutsuu `SolkiArvioijaService.lahetaArvioijaKasin`ia, joka ohittaa kytkimen — yksittäinen lähetys on se tapa, jolla integraatiota kokeillaan ennen automaattisen liikenteen avaamista. Siksi `SolkiArvioijaClientImpl` ja `SolkiArvioijaServiceImpl` ovat **ehdottomia beaneja**; aiempi `@ConditionalOnProperty` + `SolkiArvioijaServiceMock` -pari poisti koko lähetyskoneiston kytkimen ollessa pois, jolloin painiketta ei voinut toteuttaa. Painike on silti **muokkauskytkimen** takana, koska POST-reitti on. Onnistunut käsin lähetys poistaa rivin lähetysjonosta ja epäonnistunut kirjaa `solki_lahetysvirhe`n normaalisti.
- `kotoutumiskoulutus/` — integrates with the Koealusta kielitesti service
- `koski/` — outbound integration to KOSKI
- `ilmoittautumisjarjestelma/` — outbound integration to the exam-registration system
- `oppijanumero/` — Oppijanumerorekisteri client
- `organisaatiot/`, `koodisto/`, `yhteystiedot/` — reference-data clients
- `auth/`, `oauth2client/` — CAS + OAuth2 (OPH virkailija SSO)
- `observability/`, `auditlogs/` — OpenTelemetry + ECS-formatted structured logs

### Cross-cutting pieces worth knowing

- **DB & migrations**: Spring JDBC (no JPA entity manager) over Flyway. Migrations in `server/src/main/resources/db/migration` (`V*__*.sql`). Schema docs are generated by `docs/build.sh` via SchemaSpy. The V-numbering has gaps (V7, V38, V46–V55, V65) left over from earlier mistakes — most notably V65 was renamed to V67 to repair an out-of-order deploy (commit `04b1d07d`). Don't reuse skipped numbers; just continue past the highest.
- **Scheduled work**: uses `db-scheduler` (kagkarlsson). Tasks are enabled/disabled per Spring profile via properties (`kitu.yki.scheduling.*`, `kitu.vkt.scheduling.*`, etc.). There's a db-scheduler UI mounted by the app; see `docs/db-scheduler/README.md`. The `db-scheduler-log` add-on is **vendored** at `server/src/main/kotlin/io/rocketbase/extension/` (port of 0.7.0 with SB4 package relocations) until an upstream SB4-compatible release exists — see the package README for the rollback procedure. Schedule strings go through `ExtendedSchedules.parse` (`util/scheduling/`): it accepts the built-in forms (`FIXED_DELAY|Ns`, `DAILY|HH:mm`, `-`) and falls back to **SPRID53 cron** (6 fields `sec min hour dom month dow`, `?` allowed, **no year field** — Quartz-style 7-field crons fail). **Gotcha for "manual"/on-demand tasks:** a `-` (disabled) schedule does **not** make a task that's triggerable from the UI — db-scheduler deliberately never creates a `scheduled_tasks` row for a disabled recurring task (and removes any existing one) in `ScheduleRecurringOnStartup`, and the UI lists only existing executions, so the task is invisible with no "Run now". To get a UI-triggerable-but-effectively-never-auto-running task, give it a rare real cron (e.g. `0 0 0 29 2 ?` = leap-year Feb 29) rather than `-`.
- **JSON**: Jackson 3 (`tools.jackson.*` packages, e.g. `tools.jackson.databind.json.JsonMapper`). Annotations still come from `com.fasterxml.jackson.annotation` (kept for backward compat). `JavaTimeModule` no longer exists — register `java.time` serializers via `SimpleModule()`. `ObjectMapper.copy()` is gone — use `.rebuild()...build()`. Accessor renames on `JsonNode`/`JsonParser`: `textValue()` → `stringValue()`, `asText()` → `asString()`, `p.text` → `p.string`. Custom deserializers should extend `ValueDeserializer<Any>` for `@JsonDeserialize(using = ...)` compatibility.
- **Config & profiles**: `application.properties` is the base; per-env overrides in `application-{local,local-opintopolku,untuva,qa,prod,e2e}.properties`. `ConditionalOnNonEmptyProperty.kt` is a custom condition used to wire beans only when a config value is set.
- **Offline dev (`local-opintopolku`)**: started by `scripts/start_offline_dev.sh` (which sets `SPRING_PROFILES_ACTIVE=local,local-opintopolku` — the override profile must come last). It needs no AWS secrets and no Untuva: ONR, organisaatiopalvelu, koodisto and CAS are replaced by in-process mocks (`/dev/mocklogin`, `/dev/oauth/token`). `MockOppijanumeroService` (profiles `test | e2e | local-opintopolku`) resolves henkilös from the fixtures in `resources/opintopolku-mocks/oppijanumerorekisteri-service/henkilo/*.json`, plus any `MockHenkilolahde` bean that contributes henkilös at runtime — fixtures win on an OID collision. The only such bean is `dev/YkiArvioijaMockHenkilolahde` (`local-opintopolku` only, so tests and e2e are unaffected): an `ApplicationRunner` that reads every `yki_arvioija` row at startup and exposes it as a henkilö, so arvioijat that exist in the local DB resolve by OID **and** by hetu instead of 404ing out of the mock ONR. It is a startup snapshot — restart after inserting arvioijat outside the app.
- **Secrets**: never hard-coded. Local dev pulls from AWS Secrets Manager via `scripts/ensure_aws_secrets.sh`. The README lists which secrets must exist manually per AWS account (`oppijanumero-password`, `kielitesti-token`, plus `tolgee-api-key` on the Test account only).
- **Auth / CAS single logout**: browser auth is CAS (Otuva) — `SingleSignOutFilter` + `CasAuthenticationFilter` in `security/cas/`. Otuva does **back-channel** single logout: on `/cas/logout` (e.g. from the virkailija-raamit menu) CAS POSTs a `logoutRequest` to the service URL and the service must invalidate **its own** session — CAS never clears the browser `SESSION` cookie. Because kitu uses **Spring Session JDBC**, the apereo filter's default in-memory `SessionMappingStorage` can't find/invalidate the DB session (and breaks across instances), so it's wired via the **static** `SingleSignOutFilter.setSessionMappingStorage(...)` to a DB-backed `JdbcSessionMappingStorage` (service-ticket→Spring-Session-id in table `cas_client_session`; `session_id` is deliberately **not** UNIQUE — one browser session can hold several tickets, OPH KJHH-2045). Don't push injected deps into an abstract base (`@WithSpan` CGLIB trap) and don't add a session-fixation strategy to the manual `CasAuthenticationFilter` — it uses `NullAuthenticatedSessionStrategy` so the session id stays stable and the login-time ST→session mapping stays valid. Consequence: `CasUserDetails` attributes (incl. `asiointikieli`, see i18n) are a **login-time snapshot** and only refresh on a real re-login.
- **Frontend**: server-rendered HTML built with `kotlinx-html-jvm`; styling via Pico.css + a small `style.css`. Client-side JS is bundled with esbuild. No SPA.
- **Modaalit ovat natiiveja, ilman JS:ää**: `html/Modal.kt` renderöi `<dialog>`in ja avaa/sulkee sen **Invoker Commands** -attribuuteilla (`commandfor` + `command="show-modal"|"close"`) — sivuilla ei ole lainkaan modaaliin liittyvää JavaScriptiä, joten kaikki nojaa selaimen natiiviin toteutukseen. **Ansa:** komentonapin **täytyy** olla `type="button"`, jos se on `<form>`in sisällä. Ilman sitä napin tyyppi jää Auto-tilaan, ja vaikka `button.type` palauttaa IDL-tasolla `"button"` eikä lomaketta lähetetä, Chromium ei aja komentoa lainkaan: `command`-tapahtumaa ei synny ja **klikkaus ei tee yhtään mitään** (näin kävi vahvistusdialogien Peruuta-napille, joka elää `formPost`in sisällä). Siksi `modalCommandButton` kirjoittaa `type = ButtonType.button` aina — älä poista sitä. Dialogin ulkopuolinen avausnappi toimi ilmankin vain siksi, ettei se kuulu mihinkään lomakkeeseen.
- **Virhesivut HTML-näkymissä**: a virkailija view signals "ei löydy" by **throwing** a `@ResponseStatus(HttpStatus.NOT_FOUND)` exception — one per domain, declared at the bottom of the owning `*ViewController.kt` (`VktSuoritusNotFoundError`, `YkiSuoritusNotFoundError`, `YkiArvioijaNotFoundError`, `KielitestiSuoritusNotFoundError`, `TehtavapankkiNotFoundError`) — and **never** by returning `ResponseEntity.notFound().build()`, which sends a bodiless 404 and shows the virkailija a blank page. **The new exception must also be listed in the `notFound` branch of `GlobalControllerExceptionHandler.handleServerException`**: that `@ExceptionHandler(Throwable)` advice wins over Spring's own `@ResponseStatus` resolution, so an unregistered exception drops into the `else` branch and renders the **500** page instead of 404. The annotation's `reason` never reaches the user (the handler renders `ErrorPage.notFound`, i.e. `UiText.Error.sivuaEiLoydy`), so it only documents intent in logs/traces. `ResponseEntity<Void>` endpoints (e.g. tehtäväpankin `/lataa`-uudelleenohjaus) throw the same way — the advice produces `text/html` regardless of the handler's declared return type. Machine-readable endpoints (`produces = ["application/json"]`, e.g. the `koski-request` debug routes) **deliberately keep** the bodiless 404; don't "fix" those. `EiLoydyVirhesivuTest` pins the HTML routes and guards the JSON exception.
- **Display tables & CSV export (`html/table/*`)**: a list view and its CSV download share one column source — an enum implementing `RenderableDisplayTableEnum<T>` (e.g. `YkiSuoritusColumn`, `VktSuoritusColumn`), where each entry supplies `entityName`, `uiHeaderValue: LocalizedString`, `urlParam`, a `getValue: (T) -> String` (the CSV/text cell) and an optional `renderHtml` (overrides the HTML cell). **Which columns appear in HTML vs CSV is decided purely by `@ColumnTags(...)`, and the two are independent include-tags**: the HTML table selects `LIST_VIEW` (`DisplayTableColumn.of<C,T>(setOf(ColumnTag.LIST_VIEW), excludeTags)` in the `*Page`), while the CSV export selects `CSV_EXPORT` — **hard-coded** inside `DisplayTableCsvRenderer.renderCsv` (via `csvAttachmentResponse<C,_>`). So to add a column to the **CSV only**, annotate it `@ColumnTags(ColumnTag.CSV_EXPORT)` **without** `LIST_VIEW` (and vice-versa; a column can carry both, one, or neither). The filter itself is `RenderableDisplayTableEnum.getByTags` (`html/table/DisplayTableEnum.kt`): keep iff the entry's tag set intersects `require` **and** does not intersect `exclude`. The remaining `ColumnTag`s are request-driven **exclude** toggles applied to both paths, computed by `*SuorituksetParams.excludeTags()`: `PERSONAL_DATA` (dropped when "piilota henkilötiedot"), `OBSOLETE` ("piilota vanhentuneet tiedot"), `VERSION_HISTORY_ONLY` (kept only in the version-history view). CSV column **order = enum declaration order**; headers come from `uiHeaderValue` and follow the UI language (see i18n gotcha #2). All rows are read from the already-materialized entity `T`, so a new column that only reads existing entity fields needs no DB/SQL/service change — just the enum entry (+ a `UiText` header label).
- **Localization (i18n)**: FI/SV/EN. `LocalizedString(fi, sv, en)` (`i18n/LocalizedString.kt`) is the multilingual primitive for **both** koodisto reference data (loaded fi/sv/en from the koodisto service via `Translations`/`LocalizationService`) and static UI chrome. UI chrome lives in the typed catalog `i18n/UiText.kt`, where each entry is `tr("dotted.key", fi = "…")` — a computed getter (or a function that `.interpolate("count" to n)`s a `{count}` placeholder for parameterized strings). **Finnish is the canonical default in code**; Swedish/English are sourced at runtime from **Tolgee** via OPH's lokalisointi proxy (see "Tolgee sourcing" below). **No** Spring `MessageSource`/`messages*.properties` — do not add them. `LocalizedString.get(lang)` returns the requested language, **falling back to `fi`** (then the literal `"<invalid LocalizedString>"`) when that language is missing — so a half-migrated page renders untranslated bits in Finnish rather than blank; this is what makes package-by-package migration safe. `toString()` resolves the **ambient** `CurrentLanguage` (it is defined as `get(CurrentLanguage.get())`), so plain string interpolation and `+` emit the current UI language. The active language is resolved **ambiently**, not threaded: a `CookieLocaleResolver("kitu_lang")` + `LocaleChangeInterceptor(paramName="lang")` (`i18n/LocalizationConfig.kt`, bean **must** be named `localeResolver`) sets Spring's `LocaleContextHolder`, and `CurrentLanguage.get()` (`i18n/CurrentLanguage.kt`, a plain `object` — **not** a `@Service`, to avoid the `@WithSpan` CGLIB trap) reads it, defaulting to FI when no request is bound. Renderers emit a translated string by writing `+someLocalizedString` directly inside a tag block (e.g. `strong { +it.title }`), via the sole helper in `i18n/HtmlLocalization.kt`: `operator fun LocalizedString.unaryPlus()`. It's a `context(tag: Tag)` function — this is why `pom.xml` enables the `-Xcontext-parameters` Kotlin flag — and, like any extension, it must be **imported** (`import fi.oph.kitu.i18n.unaryPlus`) in each file that uses it. (There is deliberately no `t()`/`l()` helper and no Spring `MessageSource`; if you need the raw `String` — e.g. for an HTML attribute — call `someLocalizedString.toString()` (which resolves the ambient `CurrentLanguage`; pass an explicit `.get(lang)` only when you need a specific language).) `object`/static-`val` renderers (`html/Page.kt`, `html/Navigation.kt`) need no signature changes. The `html/Common.kt` article helpers are named **`errorMessage(LocalizedString)` / `warningMessage(LocalizedString)`** — not `error`/`warning` — precisely because a `FlowContent.error(String)` would let an accidental `error("literal")` silently resolve to Kotlin's stdlib `kotlin.error(Any): Nothing` (throws at runtime) instead of rendering an article. Keep those names distinct from `kotlin.error`. Wrap fi-only text as `LocalizedString(fi = "…")` during incremental migration. **Tolgee sourcing:** `tr(key, fi)` returns `LocalizedString.withTolgeeKey(key, fi)` — the object carries the Tolgee **key** and resolves sv/en **lazily** from `TolgeeMessages` on each `get()`/`toString()`/`interpolate()`/`contains()` (the key is a `private var` outside the data-class ctor, so `equals`/`hashCode`/`copy` ignore it). Because resolution is lazy, a value stored in a `val` (e.g. a column-enum `uiHeaderValue`) **no longer freezes** — it tracks `LokalisointiScheduledTasks` refreshes, so the computed-getter / `when`-getter ceremony below still works but is no longer strictly required to avoid the freeze. When the store is empty or a key/locale is missing, `get()`'s fi fallback yields Finnish. `TolgeeMessages` (`i18n/TolgeeMessages.kt`) is a plain `object` store filled at startup by `LokalisointiLoader` (an `ApplicationRunner`) which calls `LokalisointiClient` — it GETs flat per-locale JSON `/lokalisointi/tolgee/{namespace}/{locale}.json` from `https://{opintopolkuHostname}` and merges fi/sv/en into `Map<key, LocalizedString>`. `LokalisointiScheduledTasks` re-fetches on a db-scheduler interval (`kitu.lokalisointi.scheduling.*`). The **entire** lokalisointi machinery (client, RestClient config, loader, scheduled task) is gated by `@ConditionalOnNonEmptyProperty("kitu.lokalisointi.namespace")` — set in untuva/qa/prod **and** in the plain `local` profile (which reads untuva's proxy) (`namespace=kielitutkintorekisteri`; the Tolgee **namespace** separates each app's translations in the shared lokalisointi service, cf. KOSKI's `koski`); in test/e2e/`local-opintopolku` the beans don't exist and the store stays empty, so everything renders in the in-code Finnish. Fetch failures never fail startup (the loader `runCatching`s and logs). No secret — the proxy serves published files. **Writing keys back to Tolgee (`i18n/tolgee/`)** — note this is a _different service_ from the read path: the lokalisointi proxy is read-only and has **no delete route**, so writes go **straight to Tolgee Cloud** (`https://app.tolgee.io`, `X-API-Key`). `tr` records each `key→fi` into `UiTextRegistry`; `UiTextWarmup` (unconditional `ApplicationRunner`, `@Order(0)`) reflectively invokes every `UiText` member returning `LocalizedString` — properties, zero-arg functions, and functions whose params are all `Long` (called with `0L`s) — so the registry is complete regardless of what's been rendered. Then `TolgeeSyncRunner` (`@Order(100)`) diffs the registry against Tolgee's namespace and **creates missing keys and hard-deletes orphans**. Consequences worth knowing: (1) the warmup now **throws at boot** if any `LocalizedString` member can't be called (an uncallable member would look like a deleted key and get purged from Tolgee, losing translator work) — a `UiText` function taking a non-`Long` param is therefore a **startup failure**, in every profile including tests; (2) the whole `tolgee` package is gated on `@ConditionalOnNonEmptyProperty("kitu.tolgee.apiKey")`, and the secret is injected **only into the QA task** (`props.name === "qa"` in `service-stack.ts`), so the secret's existence _is_ the environment restriction — there's no profile check; (3) deletes are capped by `max(kitu.tolgee.sync.minDeleteAllowance, maxDeleteRatio × Tolgee key count)` (default `max(5, 10%)`) — over the cap, creates still run, deletes are skipped, and the home page shows a warning driven by `TolgeeSyncStatus.last` (`HomePage.tolgeeSyncWarning`); (4) `resolution: NEW` means an existing Tolgee source text is never overwritten, so **rename the key when a Finnish string's meaning changes**; (5) `kitu.tolgee.sync.dryRun=true` logs the diff without writing. `TolgeeClient` is an interface (impl `TolgeeClientImpl`) purely so tests can fake it with `object :` — this repo has no mocking library. Gotchas: (1) `Navigation.mainNavigation` **must stay a computed `val … get()`** (not a stored `val`): it references `UiText.Nav.*`, and a stored `val` would freeze those at class-load (before Tolgee loads), pinning the nav to Finnish; the getter rebuilds the list per render so it picks up loaded translations. (2) Table/CSV column headers are `DisplayTableEnum.uiHeaderValue: LocalizedString` (not `String`), resolved via `CurrentLanguage` in **both** the HTML table and `DisplayTableCsvRenderer` — so CSV **follows the UI language** (the old `.language(Language.FI)` pin in `VktSuoritusService.findEnrichedForCsv` was removed). CSV is served via `StreamingResponseBody` on an async thread where `LocaleContextHolder` is **unbound**, so `csvAttachmentResponse` captures the request language and re-binds it there with `CurrentLanguage.withLanguage(lang){…}` — without that, headers/enums would resolve to FI while koodisto cell values (resolved on the request thread) follow the UI language, giving a mixed-language file. If you ever need a fixed-language CSV again, re-pin `.language(...)` on the `translationBuilder()` and drop the `withLanguage` wrap. (3) There is no language-switcher UI yet, but the default UI language **follows the virkailija's Opintopolku `asiointikieli`**: Otuva CAS does **not** release the user's language (its attribute set is fixed — `oidHenkilo`/`idpEntityId`/`kayttajaTyyppi`/`roles`/`sessionindex`), so `CasUserDetailsService` fetches it from ONR (`getHenkiloByHenkiloOid(oid).asiointiKieli.kieliKoodi`, `getOrNull` → FI on failure) **once at login** and stores it on `CasUserDetails.asiointikieli`; `LocalizationConfig` feeds it as the default via `CookieLocaleResolver.setDefaultLocaleFunction { … }` (Spring 7 **removed** the overridable `determineDefaultLocale` — `setDefaultLocaleFunction` is its intended replacement) **only when no `kitu_lang` cookie is set**. Precedence: explicit `?lang=` (cookie) **>** Opintopolku `asiointikieli` **>** FI. Wiring the ONR dep meant injecting the `CasUserDetailsService` **bean** into `CasConfig` (it previously `new`ed a no-arg instance). The `?lang=`/cookie plumbing already works. Migrated to `UiText` so far: shared chrome (`Page`, `Navigation`, `ErrorPage`, `ErrorsArticle`, `Time`), the shared table/filter/CSV framework (`html/table/*`), the **`vkt`, `yki`, and `kotoutumiskoulutus` suoritukset views** (pages, column headers, filters, infoTable labels), and the koto **tehtäväpankki** pages (`kotoutumiskoulutus/koealusta/tehtavapankki/*` — incl. the ~32 Moodle question-type + ~34 metadata + language-name labels; the `moodleTehtavatyyppiNimet`/`languageLabels` `mapOf` lookups were rewritten as call-time `when`-functions returning `UiText.Koto.*`, since a top-level `val` map would **freeze** the translations at class-load). **Enum display values are localized too**, via the same class-load-freeze fix: `Arviointitila`/`TutkinnonOsa` `viewText` and `VktArvioinninTila` `nimi` were changed from enum-constructor `val`s to **computed `get() = when(this){ … -> UiText.X }.toString()`** properties (call sites reading `.viewText`/`.nimi` are unchanged), and `YkiViewController.ONR_UNAVAILABLE_WARNING` became a computed `val get()`. **This `when`-getter is the standard recipe** for any enum/companion display `val` you want translated. Still hardcoded Finnish, deliberately: `*ApiController` OpenAPI + API-response error strings (external-API audience); `Arvosana.arvosana` (a `@get:JsonValue` **serialization** value, not pure display — must stay a fixed string); and koodisto `nimi` (loaded multilingually from the koodisto service via `LocalizationService`/`Translations`, a separate mechanism).
- **Typed errors**: Arrow's `arrow.core.Either<E, V>` (left = error, right = value) is the project's convention for propagating domain errors out of services — prefer returning `Either` over throwing. Project-specific helpers live in `util/result/EitherExtensions.kt` (`getOrThrow` and `splitIntoValuesAndErrors`). `Either.fold(ifLeft, ifRight)` (note: ifLeft is the **first** named arg, opposite of the legacy `TypedResult.fold(onSuccess, onFailure)` order — always use named args).
- **Validation**: validators implement `Validation<T>` (`util/validation/Validation.kt`) — a three-phase pipeline of `validateBeforeEnrichment` → `enrich` → `validateAfterEnrichment` run by `validateAndEnrich`. The two `validate*` phases use the `ValidationRaise` typealias (= `Raise<NonEmptyList<ValidationError>>`) as their receiver and return `Unit` — the type system thus prevents transforming the value inside them. The sibling typealias `ValidationResult<T> = Either<NonEmptyList<ValidationError>, T>` covers the Either-shaped result. All transformation/derivation lives in `enrich`, whose receiver is the narrower `EnrichmentRaise` (= `Raise<ValidationError.EnrichmentError>`) — it may fail, but only with a single enrichment error, not an accumulated list. Checks that depend on the post-enrichment shape go in `validateAfterEnrichment` — see `YkiSuoritusValidation` where `enrich` optionally recomputes `arviointitila` via `laskeArviointitila` (only when `kitu.yki.convertLegacyArviointitila.enabled`, else passes the value through unchanged) and `validateAfterEnrichment` enforces "at least one osakoe" (`validateOsakokeitaOnAtLeastOne`, on the raw `osat`) plus that the arviointitila matches the arvosanat (`validateArviointitilaVastaaArvosanoja`). Compose sub-validators inside an `accumulate { … }` block (from `arrow.core.raise.accumulate`, `@OptIn(ExperimentalRaiseAccumulateApi::class)`), wrapping each call in `accumulating { … }` so all errors are collected in parallel rather than short-circuiting. Use `mapOrAccumulate` over collections, and `ensure` / `ensureNotNull` for predicates. Sub-validators that themselves accumulate take `RaiseAccumulate<ValidationError>` and nest further `accumulating { … }` blocks inside. Controller boundary uses `validation.validateAndEnrich(…).getOrThrow()` (extension in `ValidationService.kt`) which throws `ValidationException(NonEmptyList<ValidationError>)` — caught by `GlobalControllerExceptionHandler` and turned into a 400.
- **Observability**: Spring's `spring-boot-starter-opentelemetry` + an explicit `opentelemetry-spring-boot-autoconfigure` dep (the latter supplies the `@WithSpan` aspect that Spring's starter drops). Traces exported OTLP to Jaeger locally (`docker-compose.yml` exposes UI on `:16686`). **Gotcha:** `@WithSpan` makes the bean a CGLIB proxy. A `@WithSpan` method **inherited from an abstract base class** reads that base class's constructor-injected fields as `null` at runtime (the proxy delegates the call in a way that skips the base-class field init), even though the same method+field on the concrete `@Service` works fine. So don't push injected dependencies (`Tracer`, repositories, `AuditLogger`) into an abstract base service — keep them on the concrete class and extract shared logic into top-level helper functions that take the deps as params (see `csvparsing/CsvExportErrorHelpers.kt`, used by `Yki*ErrorService`).
- **RestClient message converters**: configure via the SB4 DSL `configureMessageConverters { cs -> cs.registerDefaults()... }`, not the deprecated `messageConverters(...)`. Use `withJsonConverter(JacksonJsonHttpMessageConverter(mapper))` to swap Jackson, and `configureMessageConvertersList { list -> list.add(0, x) }` when ordering matters. Any `RestClient` that reads a JSON body into `String` (including `retrieveEntitySafely(String::class.java)`) must call `.withLenientStringConverter()` from `restclient/RestClientExtensions.kt` — Spring 7's default `StringHttpMessageConverter` only advertises `text/*`, so without the helper the call fails inside Jackson.
- **Spring HATEOAS 3 `linkTo` DSL**: tracks the controller invocation via the lambda's **return value** (not a thread-local), so the lambda signature must be `(C) -> Any`. A `C.() -> Unit` receiver lambda collapses to `Unit` and bypasses the proxy's `LastInvocationAware` tracking — see `html/Navigation.kt`.
- **Testcontainers 2.x**: artifacts are prefixed (`testcontainers-postgresql`, `testcontainers-junit-jupiter`) and `PostgreSQLContainer` moved to `org.testcontainers.postgresql.PostgreSQLContainer` (no generic parameter). On macOS set `DOCKER_HOST="unix://${HOME}/.docker/run/docker.sock"` if the socket isn't auto-detected.

- **Lambda runtimes are never pinned, and orphan stacks are the hazard**: the one Lambda the repo owns (`koski-audit-logs-integration-stack.ts`) uses `Runtime.NODEJS_LATEST`, and CDK's own custom-resource Lambdas use `determineLatestNodeRuntimeName()` — both _variable_ values that move when `aws-cdk-lib` is bumped. Renovate automerges those bumps and every `main` push redeploys, so runtimes stay current by themselves; **do not pin a runtime to "fix" a deprecation warning**. What actually goes stale is a CloudFormation stack that was renamed or deleted in code but never deleted in AWS: CDK stops managing it and its resources freeze forever (this is where every `nodejs20.x` Lambda in this project came from — `Prod-AlarmsStack`, `CertificateStack`, and the writer left behind in the legacy `DnsStack`). **When you remove or rename a stack, delete the old CFN stack in every account in the same change.** `infra/scripts/audit-deployed-stacks.sh` (run weekly by `.github/workflows/aws-audit.yml`) diffs deployed stacks and Lambda runtimes against the synthesized app and reports the drift; `alarms-stack.ts` additionally forwards `aws.health` `scheduledChange` events to Slack so EOL notices are seen. Two related traps: `PhysicalName.GENERATE_IF_NEEDED` on the alarms SNS topics is what keeps the us-east-1 ↔ eu-west-1 sharing free of `crossRegionReferences` (removing it re-materializes a pair of custom-resource Lambdas per stack), and the per-env `DnsStack` that owns the Route53 zone is _deliberately_ outside the CDK app — the in-app `<Env>/Dns` only does `HostedZone.fromLookup` and synthesizes to an empty stack.

### Deployments

`main` pushes auto-deploy through `.github/workflows/build.yml`: server/e2e/lint run in parallel → image is built and pushed to the `Util` account ECR → then `Dev` → `Test` → `Prod` via `_deploy-env.yml`. Three AWS accounts per README: dev `682033502734`, test `961341546901`, prod `515966535475`; shared utility account `961341524988`.

**Renovate ja `infra/package-lock.json`:** Renovate ei osaa päivittää lockia `aws-cdk-lib`ille (ainoa `bundleDependencies`-riippuvuus), vaan jättää `renovate/artifacts`-statuksen punaiseksi ja avaa PR:n jossa on muuttunut **vain `infra/package.json`**. Kerran desynkatussa puussa myös `aws-cdk`-nostot epäonnistuvat samalla tavalla, ja `npm ci` kaatuu vasta mainissa. `^`-alueelliset riippuvuudet (aws-sdk-js-v3 yms.) eivät kärsi tästä, koska Renovate päivittää niiden lockin omalla `updateLockedDependency`-koodillaan ajamatta npm:ää lainkaan. Kolme toisiaan täydentävää suojaa, joista mikään ei yksin riitä: `skipInstalls: false` (täysi `npm install` `--package-lock-only`:n sijaan, jolloin niputetut riippuvuudet resolvoituvat), `platformAutomerge: false` (Renovate mergeää vasta kun **jokainen** tarkistus on vihreä — GitHubin oma automerge odottaa vain _pakollisia_) ja `Infra lockfile in sync` -työ pakollisena tarkistuksena repon rulesetissä. **Älä lisää `renovate/artifacts`ia pakolliseksi tarkistukseksi** — ihmisten PR:t eivät koskaan saa sitä ja jäisivät ikuisesti jumiin.

## Conventions

- **Language**: user-facing text, commit messages, and PR titles are in Finnish. Kotlin/TS identifiers are Finnish/English mix following existing usage in the touched package — follow the surrounding file.
- **Formatting**: ktlint (K2 mode, format-on-save in IDEA) for Kotlin; prettier for TS/JSON/YAML/MD; shellcheck for `scripts/*.sh`. `.git-blame-ignore-revs` tracks formatting-only commits — add new bulk-reformat commits there.
- **Always run `./scripts/format.sh` before reporting a task done** whenever TS/JSON/YAML/MD (or Kotlin) files have been touched. The script runs `prettier --write .` and `ktlint --format`, matching what `check-formatting.sh` enforces in CI.
- **Banned dependencies**: `pom.xml` enforces exclusions for vulnerable `bouncycastle` and `xmlunit-core` versions; don't let transitive updates reintroduce them.
- **Keep `infra/README.md` accurate**: any change under `infra/lib/` or `infra/bin/` that affects which stacks exist, what they create, IAM identities, cross-account wiring, manual prerequisites (DNS zones, secrets, KOSKI-side resources), or the Slack/alarms/investigation flow must update `infra/README.md` in the same commit.
